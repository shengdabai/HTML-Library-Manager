# HTML Manager — contributor instructions

## Prerequisites
Use macOS with Python 3.10 or later. Runtime requires only the Python standard library. Browser tests reuse an installed Playwright package; set PLAYWRIGHT_MODULE to its index.mjs before invoking the test runner.

## Project map
Read library.py for read-only discovery and extractive topic labels. Read manager.py for persistence, export and optional loopback HTTP APIs. Read editor.py for the editor backend (preview serving, save/versions, annotations, uploads, Codex jobs) and editor.html for the editing workbench. Read index.html for UI tokens and escaped text rendering. Read docs/PRD.md for scope and docs/TECH.md for trust boundaries.

## Workflow
1. Preserve original HTML files. Index metadata without executing HTML scripts or uploading source content.
2. Before revising existing project files, save named files with ai-file-checkpoint and record its ID in .omc/plans/html-manager-todo.md.
3. Run python3 manager.py --help to check CLI syntax. Run python3 manager.py scan --root <directory> --state-dir <test-state> for a bounded scan. With no source arguments, use documented personal source defaults.
4. Run python3 -m unittest -v test_library.py test_manager.py test_editor.py after changes to discovery, state, editor or HTTP behavior. test_editor.py and test_editor_browser.mjs use a fake codex script; never call the real Codex CLI from automated tests.
5. Run PLAYWRIGHT_MODULE=/opt/homebrew/lib/node_modules/playwright/index.mjs (the Playwright installed on this machine, 1.57.0) node test_browser.mjs for 390, 768 and 1440 viewport acceptance against a temporary fixture server. Production data is excluded from fixture tests. Fixtures are created next to the test scripts (or under ~/Desktop if the scripts run from a copy outside non-hidden $HOME paths) because manager.validate_root rejects os.tmpdir(); do not loosen validate_root. test_browser.mjs records the /usr/bin/open argv instead of launching the desktop browser and deletes its fixture directory on exit. Set HTML_MANAGER_NATIVE_OPEN=1 only for a requested visible check; that mode really opens the fixture and keeps it, so remove the printed FIXTURE_DIRECTORY afterwards. Run the same PLAYWRIGHT_MODULE with node test_mobile.mjs for the offline export on a 390px phone viewport. Run the same PLAYWRIGHT_MODULE with node test_editor_browser.mjs after editor changes. All three browser scripts launch ~/.local/bin/chrome-headless-shell (override with CHROME_HEADLESS_SHELL) and must not use a browser channel. They do not use the Chromium revision that Playwright pins, because each Playwright release pins one exact revision (1.57.0 pins chromium_headless_shell-1200) while the cache holds other revisions (1208 to 1234), so a bare chromium.launch() fails with "Executable doesn't exist"; the wrapper script picks the newest cached headless shell. The WebKit leg of test_mobile.mjs needs the exact WebKit revision of the installed Playwright (`npx playwright install webkit`; the cache holds webkit-2287 and 1.57.0 expects webkit-2227). If it is missing, test_mobile.mjs prints "WEBKIT NOT INSTALLED - NOT RUN" and ends with "WEBKIT UNVERIFIED" in the SUMMARY line: that is not a pass. Set REQUIRE_WEBKIT=1 to make a missing WebKit fail the run. Do not download browsers without the owner's approval.
6. For temporary runtime testing, run python3 manager.py serve --root <fixture-directory> --state-dir <test-state> --port 0. Stop only the server process created by this test.
7. Export a new portable catalog with python3 manager.py export --out <new-file.html>. Existing output is refused unless --force is given; --force writes a temp file in the same directory and os.replace()s it, which is how 更新静态目录.command refreshes the pinned 16-飞书HTML/00-HTML资料库管理器.html in place (that pinned export is scoped to --root 16-飞书HTML with --state-dir ~/.local/share/html-manager/pinned-16 so it stays small and never touches the serve cache). The theme select value is a JSON [root, name] pair; if the selected theme disappears after a refresh the UI clears it and re-queries. Theme folders (first-level subdirectories under a root) are exposed as `themes` in /api/library and the snapshot, grouped by root. Export includes local filenames, paths and searchable text; keep it private to the owner; desktop exports sync to the owner's iCloud.
8. Before persistent deployment or login startup installation, resolve the original dictation's deployment ambiguity. Do not infer deployment consent from passing tests.
9. Record PASS, REVISE, WAITING or N/A per PRD item in the ledger. Include source SHA-256, test command and time. Report pending user-usage evidence separately from machine checks.

## Error handling and report
If a root is unavailable or a cap is reached, report partial coverage and preserve cached unverified items. If source-open fails, display the failure and suggest refresh. After review, report findings with file/line, reproduction, severity and disposition. Never fabricate NLPM plugin scores for Python/HTML runtime code.

## Scope boundary
Implement search, short labels, favorites, history, directory settings, source-open and the service-mode editor (explicit save or applied Codex job only, always with a version backup). Keep editor previews script-disabled. Leave deletion, cloud upload, login/payment and unattended startup out of this version.
